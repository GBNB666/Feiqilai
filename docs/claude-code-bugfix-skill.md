# Claude Code 高效修 Bug 四步法

核心思想：不说"修一下这个bug"，而是给 AI 一套**可验证的返工标准**。

---

## 一、给 AI 完整的 Bug 复现包

不要一句话描述，给三样东西：

```
1. 完整报错文案（直接贴，别转述）
2. 复现路径（从哪个页面开始，点哪几个按钮，到哪一步炸了）
3. 预期 vs 实际（你希望看到什么，实际发生了什么）
```

**对比效果：**

| 模糊说法 | 精准说法 |
|---|---|
| "登录坏了" | 登录成功不跳转，控制台报 `Cannot read property 'token' of undefined`，/login → 填账号密码 → 点登录 → 无响应 |

---

## 二、圈定修改范围

明确告诉 AI **只动哪些文件、哪些不能碰**，防止修一个小 Bug 改崩一大片。

```
只改：login.js 中 token 读取逻辑
不动：全局路由、用户数据接口、样式文件、其他页面的 token 引用
```

---

## 三、列出验收清单（最关键）

改完代码后 AI 自己对照检查，通过才算完：

- [ ] 控制台无报错
- [ ] 登录成功跳转首页
- [ ] token 正常存入 localStorage
- [ ] 原有账号密码校验不受影响
- [ ] 密码错误时仍然正常提示（不新增 Bug）

---

## 四、要求 AI 自检 + 周边排查

每次改完后，让 AI 做两件事：

1. **自查**：按验收清单逐条过一遍
2. **周边排查**：搜索同文件里有没有同类问题（比如还有没有别的 `xxx.yyy` 链式取值可能炸的地方）

没通过验收就直接说"第 X 条没过"，不用重新描述整件事。

---

## 一句话速记

> 复现包 → 圈范围 → 验收到每一项 → AI 先自检再交差
